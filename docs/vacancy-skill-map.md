# Что здесь есть — и почему именно это

Этот проект не собирался наугад. Параллельно с разработкой велась систематическая выгрузка
и разбор ~80 вакансий (AI/ML/LLM/MLOps, РФ, 2026) и 24 транскриптов реальных технических
интервью — что реально спрашивают, а не что кажется важным на бумаге. Ниже — прямая связь
между тем, что здесь реализовано, и тем, что этим разбором подтверждено.

## Сигнал с интервью: что реально спрашивают

24 интервью, частота темы = в скольких из них она поднималась:

| Тема на интервью | Частота | Что в проекте отвечает на это |
|---|---|---|
| RAG / retrieval / chunking / reranking / eval | 15+ / 24 | Hybrid dense+sparse retrieval, reranker, 6 задокументированных retrieval-экспериментов с числами — [метрики](../README.md#метрики-и-эксперименты) |
| Production: FastAPI / Docker / monitoring / deployment | 8+ / 24 | FastAPI + rate limiting, Docker Compose (10+ сервисов), circuit breaker + graceful degradation, Langfuse tracing |
| LLM agents / function calling / LangGraph / MCP / structured output | 7+ / 24 | ReAct agentic-маршрут, MCP tool-сервер, LangGraph (точечно — дебаты), framework-less agent loop spike |
| LLM inference / vLLM / KV-cache / квантизация | 6+ / 24 | Self-hosted vLLM (reranker + опциональная генерация, Qwen3-4B-AWQ), это же окружение переиспользовано под LoRA-инференс |
| Python fundamentals / async / OOP | 8+ / 24 | Не витрина — читается по всему коду (`app/core/*`) |
| Классический ML / метрики / вероятность | 7+ / 24 | Вне охвата проекта осознанно (см. пробелы ниже) |
| SQL / vector DB / Redis | 5+ / 24 | Qdrant (hybrid), Redis (answer cache) — без Postgres, см. пробелы |

Полная разбивка по времени и приоритетам — внутренний артефакт разбора, здесь приведён только
вывод, применимый к README.

## Рыночный сигнал: куда смещается спрос

Разбор вакансий (июль 2026, РФ) показал: MLOps/AI Platform Engineer растёт **+50% год к
году** — быстрее чистого backend или DevOps, и медианная зарплата выше при том же грейде.
Ключевой нюанс: MLOps — это расширение DevOps в сторону ML, не отдельная профессия с нуля.
Отсюда решение — приоритизировать этот трек, и три вещи уже наработаны здесь как побочный
эффект инженерной дисциплины проекта, а не ради резюме:

| Наработано в проекте | Прямой аналог того, что спрашивает MLOps-вакансия |
|---|---|
| Docker Compose, 10+ связанных сервисов | Container orchestration mindset (ступень перед Kubernetes) |
| Circuit breaker + graceful degradation (`app/core/resilience.py`) | Системная надёжность / SRE-мышление |
| Self-hosted vLLM inference (reranker, опц. генерация) | Это и есть ML-инфраструктура в проде, не абстракция |
| Langfuse tracing + бизнес-метрики на трейсе | Аналог Prometheus/Grafana-подхода к observability |
| LoRA router: hypothesis → experiment → metrics → decision (`docs/rnd-decision-log.md`) | R&D-дисциплина, которую спрашивают на agentic/research-ролях |

## Честные пробелы — не забытое, а взвешенное решение

Разбор тех же вакансий называет это как «must have» или устойчиво повторяющийся паттерн —
здесь этого пока нет, и это зафиксировано явно, а не спрятано:

| Пробел | Насколько частый сигнал | Статус |
|---|---|---|
| **Kubernetes** | Must-have для DevOps/MLOps в 2026 (обязательный стек рынка) | Приоритет №1 плана обучения — Docker Compose есть, k8s manifests/Helm нет |
| **Prometheus / Grafana / OpenTelemetry** | 5+ вакансий поверх Langfuse-трейсинга | Приоритет №2 — Langfuse закрывает LLM-трейсинг, не общий метрики/алерты слой |
| **Terraform** | Стандарт для DevOps/MLOps ролей 2026 | Не начато |
| **MLflow / DVC** | Трекинг экспериментов / версионирование данных | LoRA-эксперименты пока логируются вручную в ноутбуке |
| **PostgreSQL** | Встречался в 6/30 разобранных вакансий | Осознанно не добавлено — уже есть реальный продакшн-опыт с Postgres вне этого проекта, дублирование не даёт нового сигнала |

Это тот же принцип, что и в разделе [«Известные ограничения»](../README.md#известные-ограничения-и-планы)
README: пробел, который не закрыт, но измерен и приоритизирован — не то же самое, что пробел,
который не заметили.
